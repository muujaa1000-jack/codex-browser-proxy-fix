# Browser Proxy Workaround Implementation Plan

> Execute inline using superpowers:executing-plans. Scope and publication are approved.

**Goal:** Publish a narrowly scoped, reversible Windows workaround with bilingual tutorials and no private material.

**Architecture:** A PowerShell module owns validation, transformation and file transactions. A small CLI discovers the plugin and dispatches Check, Apply or Restore. Tests inject a synthetic fingerprint into module scope, never through the public CLI.

**Tech Stack:** PowerShell 7 and built-in .NET; no additional runtime packages.

## Global constraints

- Windows only; minimum PowerShell 7.0.
- Only version 26.903.71938 and the verified original SHA256 in the approved spec.
- Explicit local HTTP proxy; no credentials, remote proxies, path/query/fragment or implicit ports.
- All public content is original and generic; neutral Git author identity.

## Task 1: guarded patch transaction

Files: `src/ProxyFix.psm1`, `tests/Run-Tests.ps1`.

Interface: `Invoke-ProxyFix -Action Check|Apply|Restore -LauncherPath <path> [-ProxyUrl <url>]` returns an object with Status and Changed. Apply creates an original backup next to the target. Restore checks both original and current bytes before replacing either file.

- [x] Write synthetic tests for Check, Apply, duplicate Apply, Restore, mismatched digest, modified patch, invalid proxy and corrupted backup.
- [x] Run `pwsh -NoProfile -File tests/Run-Tests.ps1` and record the expected failure before the module exists.
- [x] Implement URL validation, SHA256 gating, exact patch recognition, atomic writes and restore; rerun the suite.

## Task 2: discovery and CLI
