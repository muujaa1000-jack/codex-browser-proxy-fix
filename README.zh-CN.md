# Codex Browser Proxy Fix

简体中文 · [English tutorial](README.md)

这是一个**非官方、按文件指纹校验的 Windows 临时修复工具**，用于一种具体情况：Codex 浏览器控制进程没有收到它访问网络所需的本机代理配置。

它不能修复所有浏览器问题。扩展未连接、Chrome 未启动、登录失败、网站限制和应用内部连接异常，都可能有不同原因。`Check` 只检查本地文件是否兼容，不能读取已经运行的进程环境，也不能单凭超时判断故障原因。

## 双击使用（v0.3.0）

解压完整文件夹，双击 **Start-Repair.cmd**。需要 Windows 和 PowerShell 7，不需要管理员权限。

1. 首次打开，核对本机 HTTP／混合代理地址，点击 **检查并修复**。窗口中的环境变量建议值不会被自动当成确认。
2. 成功后仅在本机记住代理地址。下次双击时，若只有一个候选插件，会自动检查修复；多个缓存版本需要先选择实际使用的版本，不会猜最新版本。
3. **恢复原文件**会使用核验过的备份恢复；**查看结果**显示本机检查详情。工具不会关闭 Codex 或 Chrome。
4. 显示“补丁已应用”后，请先完成正在运行的任务，再重启 Codex 并复测网页。显示“补丁已存在”则无需重复修改。

新版启动验证会清除测试进程继承的代理变量，检查语法、工具握手、工具列表和正常退出。这不会操作浏览器，也不能证明外网可达。若验证失败，只在文件未再次变化时撤回本次新补丁；已有补丁不会因为验证失败被删除。旧启动器只做文件验证。

代理地址保存在 `%LOCALAPPDATA%\CodexBrowserProxyFix\settings.json`，不放入仓库、不上传；工具不扫描端口。它支持版本号和目录编号变化，但如果启动器代码本身变化，仍可能需要更新工具。

若下载文件被系统阻止，先审阅文件，再仅解除本工具文件的下载标记，无需修改执行策略：

```powershell
'./Start-Repair.cmd','./Repair-Window.ps1','./Repair-CodexBrowserProxy.ps1','./src/ProxyFix.psm1','./src/RepairWorkflow.psm1','./src/startup-probe.mjs' | ForEach-Object { Unblock-File -LiteralPath $_ }
```

自定义 Codex 目录可使用：`pwsh -NoProfile -STA -File ./Repair-Window.ps1 -CodexHome '你的绝对本地目录'`。

2026-09-18，用户反馈：再次更新 Codex 后，实测双击工具仍可使用。这是单一用户环境的实测反馈，不代表保证兼容所有后续版本；未知启动器内容仍会被拒绝。

## 第一步：下载并打开工具

从本仓库的 **Code → Download ZIP** 或 **Releases** 下载源码 ZIP，解压后，在该文件夹打开 **PowerShell 7**。不要在 ZIP 压缩包内直接运行脚本。

检查终端版本：

```powershell
$PSVersionTable.PSVersion
```

如果主版本号是 5，请改用 PowerShell 7。若下载的文件被 PowerShell 阻止执行，先阅读脚本，确认后只解除这两个文件的下载标记，不必修改全局执行策略：

```powershell
Unblock-File -LiteralPath .\Repair-CodexBrowserProxy.ps1
Unblock-File -LiteralPath .\src\ProxyFix.psm1
```

本工具不要求管理员终端、修改全局执行策略、重装浏览器扩展或更改登录。

## 第二步：检查兼容性

至少打开过一次 Codex，让它生成插件启动配置。应用补丁前先完成正在运行的任务；脚本不会强制关闭应用。

```powershell
pwsh -NoProfile -File .\Repair-CodexBrowserProxy.ps1 -Action Check
```

- **Compatible**：文件与已验证的原始启动器一致。只代表可兼容，不代表你一定需要修复。
- **Patched**：识别到本工具生成的完整补丁和对应的原始备份。
- **Unsupported**：文件不同、曾被手工修改，或备份无法识别／已损坏。检查不会修改文件。
- **No unique plugin candidate**：没有唯一候选插件，可能存在多个缓存版本。先在 Codex 中确认实际使用的版本；如果是支持版本，在**每条命令**后加 `-PluginVersion` 和实际版本号。不要猜哪个版本正在使用。

默认从环境变量 `CODEX_HOME` 查找；未设置时使用 `$env:USERPROFILE\.codex`。自定义安装可通过 `-CodexHome` 指定绝对本地目录。链接／重定向目录、UNC 网络路径和不支持的目录结构会被拒绝。

## 第三步：填写自己的代理地址并修复

在你使用的代理软件中查找 **HTTP 或 mixed／混合代理监听端口**，不要填 SOCKS 专用端口。先启动代理软件。

下面的 **7890 只是示例**，脚本不会自动把它当作你的端口。请替换成实际端口：

```powershell
pwsh -NoProfile -File .\Repair-CodexBrowserProxy.ps1 -Action Apply -ProxyUrl 'http://127.0.0.1:7890'
```

如果代理只监听 IPv6 本机地址，使用 `http://[::1]:你的数字端口`。本版本不支持外部主机、用户名密码、URL 路径、查询参数、片段、HTTPS 或 SOCKS 地址。不要填写账号凭据。

应用前只尝试连接你指定的本机 TCP 端口。这只能证明该端口有程序监听，**不能证明它是 HTTP 代理，也不能证明它能访问外网**。脚本不会向外部网站发送测试请求，也不会使用登录凭据。

预期结果为 **Applied**。原始文件备份保存在启动器旁边，文件名是 `<启动器文件名>.codex-browser-proxy-fix.original.bak`（启动器名为 `launch.mjs` 或 `cua-repl.mjs`），请保留。使用同一地址重复运行会返回 **AlreadyPatched**，不会重复插入代码。需要更换地址时，先恢复，再重新修复。

## 第四步：重启，验收真实网页操作

完成正在运行的任务后，完全退出并重新打开 Codex。需要使用 Chrome 控制时，也要打开 Chrome。只重置 JavaScript 会话不一定会重新启动工具进程。

可以把下面这段发给 Codex：

> 分别复测 Chrome 和内置浏览器控制：打开 https://example.com，读取标题和正文，点击 Learn more 并读取目标页面，然后返回上一页。只关闭本次测试的标签页。分别报告两种浏览器的结果。

两种浏览器都应打开 **Example Domain**，点击进入 **IANA Example Domains**，并成功返回。文件修改成功、工具启动成功，都不能替代网页验收。若仍失败，记录具体报错和失败的浏览器，继续排查相应原因，不要反复叠加补丁。

## 第五步：恢复原文件

```powershell
pwsh -NoProfile -File .\Repair-CodexBrowserProxy.ps1 -Action Restore
```

预期结果为 **Restored**；已经是原文件时返回 **AlreadyOriginal**。再次重启 Codex 后，恢复的启动器才会生效。备份文件会继续保留。

恢复前会检查原始备份指纹，以及当前文件是否与本工具生成的补丁完全一致。后续编辑过的文件、无法识别的升级文件，都不会被旧备份覆盖。如果备份丢失／损坏，或之前打过另一份手工补丁，应使用自己核验过的原始备份，或应用正常的插件重装／更新方式恢复。不要从陌生人的电脑复制启动器文件。

## 具体修改了什么

只在通过校验的启动器中，为子进程补充四个环境变量的默认值：

- `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`：你填写的本机 HTTP 代理地址。
- `NO_PROXY`：`localhost,127.0.0.1,::1`。

如果原有大写环境变量已设置且非空，优先保留原值。使用受影响的浏览器工具时，本机代理需要保持可用。

脚本不修改系统代理、DNS、注册表、账号登录、浏览器用户数据、权限列表或安全检查；不启动／停止 Codex、Chrome 或代理软件；没有遥测或上传。读取插件启动配置只是为了定位和核对启动器，脚本不会执行配置中的程序命令。

前期观察到的桌面版本会在启动时删除普通用户配置中的 `mcp_servers.cua_repl` 覆盖项，因此这里修正实际启动脚本。应用升级、重装或强制刷新插件可能覆盖补丁。遇到这些情况需要重新检查兼容性，不建议设置自动反复打补丁的任务。

## 常见结果与处理

| 结果 | 下一步 |
| --- | --- |
| 本机代理端口无法连接 | 启动代理软件，核对 HTTP／混合代理端口。 |
| Compatible，但你没有浏览器故障 | 保持原状，不必应用补丁。 |
| Chrome 不可用 | 打开 Chrome，检查它与 Codex 扩展的连接。 |
| Applied，但网页仍打不开 | 执行上面的真实网页验收；可能不是同一个原因。 |
| 更新后显示 Unsupported | 停止修改，这个文件尚未被本版本验证。 |
| 拒绝访问／链接路径被拒绝 | 在本机检查安装情况，不要为强行执行而扩大权限。 |
